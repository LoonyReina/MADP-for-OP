# Roadmap

## Prepared edition

- English/Chinese entry pages, architecture and explicit evidence boundaries.
- Two-process demo with real Gateway retention and independent ACK.
- Reviewed prompt/Windows artifact fixes and isolated wheel qualification.
- Research strategy distinguished from historical runtime gates.

## Next engineering slice

1. Export a trusted standalone host contract for writer admission and explicit
   submit/hold. Test that HOLD cannot be overridden by old auto-submit paths;
   avoid another competing state machine.
2. Extract portable diagnostic/result ports without private test-plan imports.
3. Provide a licensed CPU operator fixture and executor adapter; qualify real
   separate harness integrations one at a time before calling them supported.
4. Add independent reproduction and platform CI for lifecycle differences.

## Showcase follow-up

Record a short walkthrough of the reproducible demo. Add a real adapter example
when qualified. Collect adoption/reproduction evidence, not unsupported speedup
claims. These materials can later support an open-source program application;
this work does not submit one or claim eligibility/endorsement.

Useful contributions: small executor ports, recovery tests, onboarding and
cross-platform qualification. Read [CONTRIBUTING](../../CONTRIBUTING.md) for
current contribution channels and publication boundaries.

## Inter-agent knowledge slice

1. Publish the interleaved-development explanation and its dependency-free
   Markov toy model as a method illustration.
2. Stabilize Markdown/JSON `TechniqueCard`, `DiagnosticCard`, `HandoffCard` and
   `EvidenceCard` exports with provenance and redaction fields.
3. Add a local index and publication scan for cross-agent cards; keep the wiki
   downstream of the workspace contract rather than a second scheduler.
4. Qualify two independent public harness adapters before describing them as
   supported integrations.

The [cross-agent wiki plan](CROSS_AGENT_WIKI.md) and [Codex for Open Source
application draft](CODEX_FOR_OPEN_SOURCE_APPLICATION.md) describe the intended
public-facing next step.
